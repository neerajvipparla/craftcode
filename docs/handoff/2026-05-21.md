## craftcode — design decisions and rationale

### Architecture
`craftcode-prod` is the **entry point** for production work. It handles context gathering, ultrathink reasoning, and produces a context doc. It then hands off to `craftcode` phases 0–7 for actual implementation discipline.

`craftcode` is the **base discipline ruleset**. Used directly for POC or when context is already established.

### Phase structure (craftcode)
- Phase 0: POC or Prod gate
- Phase 1: Design interrogation (grill-me style) + **data structure questions** (added this session)
- Phase 2: **Data structure selection table** + design pattern table (split added this session)
- Phase 3: Implementation phase doc with backtrack notation
- Phase 4: Module AI-doc (CORE DATA STRUCTURES field added this session)
- Phase 5: Time complexity annotation (DS named in every annotation — added this session)
- Phase 6: Test placement (`tests/<module>/` only)
- Phase 7: Integration seal (DS match check, unbounded growth check — added this session)

### Key design decisions
- **Data structures are first-class** — DS choice must be resolved before pattern selection. Wrong DS propagates into every interface that passes it; expensive to fix later.
- **Module AI-docs are for the next AI editor, not humans** — includes `CORE DATA STRUCTURES`, `TO MODIFY BEHAVIOR`, `DO NOT`, `EXTENSION POINT` blocks.
- **Haiku subagent for all doc writes** — fire-and-continue after each phase. Saves main-model tokens for implementation.
- **Backtrack notation** — if Phase N forces changes to Phase M, insert `Phase N → Phase M.1 (backtrack)` in the phase doc before Phase N+1. Implement M.1 before continuing.
- **Handoff before compaction** — Haiku subagent writes `docs/handoff/HANDOFF.md` before context compacts.
- **Tests only in `tests/<module-name>/`** — zero exceptions. No `_test.go` alongside source.

### craftcode-prod — design decisions
- **KNOW / ASSUMED / GAP framework** — explicit written reasoning after reading all docs. Every ASSUMED item must be verified by file read before use.
- **Context doc before phase doc** — `docs/context/<feature-YYYY-MM-DD>.md` is the anti-hallucination anchor. All implementation claims must trace to it.
- **Maximum 5–7 questions** — if you need more, you haven't read enough. Go back to Step 1.
- **Evidence-anchored questions** — every question cites what you read that makes it necessary.
- **Context doc dispatched via Haiku subagent** — preserves main-model tokens.

### What was intentionally NOT changed in craftcode
- Phase numbering (0–7) kept stable — agent rejected a version that renumbered phases
- Haiku subagent section kept fully detailed — agent rejected a simplified version that lost subagent dispatch precision
- Execution Discipline section kept — one phase at a time, BLOCKED notation, mandatory return
